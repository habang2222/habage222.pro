# 사진 빠른 분류

Android 휴대전화에서 여러 사진을 고른 뒤 사진마다 앨범 이름 버튼을 하나 이상 선택하고 **다음**을 눌러 각 로컬 갤러리 앨범으로 복사하는 오프라인 앱입니다. 원본 사진은 수정하거나 삭제하지 않습니다.

## 실행과 권한 확인

처음 실행하면 앱이 사진 접근 용도를 설명합니다. 사용자가 **확인하고 권한 요청**을 누른 다음 Android의 시스템 권한 창에서 허용 여부를 정합니다. **나중에**를 누르면 권한 없이 기본 화면을 볼 수 있으며, **앨범 추가**에서 다시 요청할 수 있습니다. Android 14 이상에서 일부 사진만 허용하면 앱에 보이는 앨범과 사진 수가 제한될 수 있습니다. 앱으로 돌아오면 권한과 앨범 목록을 다시 확인합니다. 권한을 계속 거부한 경우에는 다시 요청하거나 Android 앱 설정으로 이동할 수 있습니다.

분류할 사진은 Android Photo Picker에서 직접 선택합니다. 이 선택 과정 자체에는 전체 사진 접근 권한이 필요하지 않습니다. 기존 기기 앨범 목록을 MediaStore에서 읽기 위해 사진 접근 권한을 요청합니다. Android 8~9에서는 공유 사진 폴더에 저장하기 위한 쓰기 권한도 함께 요청합니다. 접근성 권한, 모든 파일 접근 권한, 인터넷 권한은 사용하지 않습니다.

## 사용 방법

1. **앨범 추가**를 눌러 표지와 사진 수가 표시된 로컬 앨범을 선택합니다. 선택하면 등록 화면으로 돌아옵니다. 원하는 앨범이 보이지 않으면 앱에서 **새 앨범**을 등록할 수 있습니다. 새 앨범은 첫 사진을 복사할 때 실제로 만들어집니다.
2. 홈에서 등록된 앨범 이름을 확인합니다. 사진 분류 화면에는 등록된 앨범 이름이 그대로 선택 버튼에 표시됩니다.
3. **사진 선택하기**에서 여러 장을 고르고 분류를 시작합니다.
4. 현재 사진을 넣을 앨범 버튼을 하나 또는 여러 개 누릅니다. 선택한 버튼은 색이 진해지며, 같은 버튼을 다시 누르면 선택이 해제됩니다. 버튼을 고르는 동안에는 복사하지 않습니다.
5. **다음**을 누르면 선택한 각 앨범에 사진을 복사한 뒤 다음 사진으로 이동합니다. 아무 앨범도 고르지 않고 **다음**을 누르면 해당 사진을 건너뜁니다.
6. 이전 사진으로 돌아가 처리 내용을 확인하거나 다른 앨범에 추가할 수 있습니다. 이미 성공한 앨범 복사는 다시 하지 않습니다. 복사 오류가 나면 현재 사진에 머물며 실패한 대상만 다시 시도할 수 있습니다.

중복 파일 이름이 있으면 `_1`, `_2`를 붙여 새 파일을 만듭니다. 여러 앨범에 한 사진을 복사해도 분류된 사진 수는 한 장으로 계산하며, **이번에 선택한 사진 목록에서 새로 복사한 파일 수**는 별도로 표시합니다. 진행 상황과 등록한 앨범은 기기에 저장됩니다.

## Google 포토에서 같은 사진이 여러 장 보일 때

한 사진을 앨범 두 곳에 넣으면 원본 한 장과 앨범마다 만들어진 복사본 한 장씩, 모두 세 개의 실제 파일이 생깁니다. Google 포토의 **사진** 화면은 여러 기기 폴더의 사진을 함께 보여 줄 수 있으므로 같은 장면이 나란히 보입니다. 사진에 촬영 날짜 정보가 없으면 새 복사본이 맨 위에 나타날 수도 있습니다. Google 포토에서 사진을 열고 **⋮ → 정보 → 세부정보**의 폴더 이름을 확인하면 각 파일의 위치를 구별할 수 있습니다.

Google 포토 앱에서 사진을 **삭제**하면 휴대전화의 같은 사진 파일도 삭제됩니다. 분류 앨범의 복사본을 삭제하면 그 앨범에서도 사라집니다. 분류 결과를 남기면서 사진 화면만 정리하려면 삭제하지 말고 아래의 숨기기 설정이나 보관처리를 사용하세요. [Google 포토 삭제 안내](https://support.google.com/photos/answer/6128858?co=GENIE.Platform%3DAndroid&hl=ko)

앱의 홈과 분류 완료 화면에 **Google 포토 정리 방법** 버튼이 있습니다. 앞으로 만드는 복사본을 한 번의 Google 포토 설정으로 숨길 수 있는 경우의 경로를 먼저 안내하고, 기존 사진의 보관처리와 삭제의 차이도 설명합니다. **Google 포토 열기**로 이동할 수 있습니다. 보관처리와 Google 포토 설정 변경은 Google 포토에서 사용자가 직접 진행합니다.

이미 분류한 사진을 **사진** 화면에서 모두 치우려면 Google 포토에서 폴더 이름을 확인한 뒤 **원본과 분류 앨범 복사본을 모두 길게 눌러 선택 → ⋮ → 보관처리**합니다. 복사본만 선택하면 원본은 계속 보입니다. 보관처리하면 사진 화면에서 숨겨져도 기기 폴더에는 남고 **컬렉션 → 보관 파일**에서 찾거나 보관 취소할 수 있습니다. [Google 포토 보관처리 안내](https://support.google.com/photos/answer/7362432?co=GENIE.Platform%3DAndroid&hl=ko)를 참고하세요.

앞으로 생길 복사본도 숨기려면 Google 포토에 **다른 앱의 콘텐츠 표시** 설정이 있는지 확인합니다. Google의 [공식 안내](https://support.google.com/photos/answer/14169846?co=GENIE.Platform%3DAndroid&hl=ko)는 **비슷한 사진 묶음 → 아래 작은 사진의 더보기 → 설정 관리** 경로를 설명합니다. 이는 사진 화면 맨 위 ⋮와 다른 메뉴입니다. **앱별 맞춤설정**에 `사진 이름별 분류`가 보이면 **모두 숨기기**를 선택할 수 있습니다. 앱이 목록에 없다면 **다른 앱의 콘텐츠 표시**를 끌 수도 있지만 다른 앱 사진도 사진 화면에서 숨겨질 수 있습니다. 이 옵션이 없거나 해당 복사본에 적용되지 않을 수도 있으며, 앱이 Google 포토 설정을 강제로 바꿀 수는 없습니다. 앱별 설정으로 복사본을 숨겨도 원본은 사진 화면에 남을 수 있습니다.

표시 설정으로 숨긴 파일은 삭제되지 않습니다. Google 포토 **컬렉션 → 기기 내**에서 해당 기기 폴더를 확인할 수 있습니다. [Google 포토의 기기 폴더 안내](https://support.google.com/photos/answer/6306652?co=GENIE.Platform%3DAndroid&hl=ko)를 참고하세요.

## 지원 범위와 갤러리 차이

Kotlin, Jetpack Compose, MVVM, Coroutines, Preferences DataStore, MediaStore, Android Photo Picker, Coil을 사용합니다. **Android 8.0(API 26) 이상**을 대상으로 하며, Android 10 이상은 MediaStore의 상대 경로와 미완료 항목 처리를 사용합니다. Android 8~9는 공유 저장소 권한과 미디어 스캔을 사용합니다.

앱의 앨범 화면은 특정 제조사의 갤러리 앱 화면이 아닙니다. MediaStore에서 실제 사진이 확인되는 로컬 `Pictures`/`DCIM` 앨범을 표시합니다. 클라우드 전용 앨범, 갤러리 내부 가상 앨범, 사진이 없는 폴더, 읽거나 저장할 수 없는 위치는 그대로 선택할 수 없습니다. 이름이 같은 앨범은 내부 식별 정보로 구분합니다. Android 파일 관리자에서 폴더나 경로를 선택하게 하지 않습니다.

## 빌드 및 설치

Android Studio에서 이 폴더를 열어 Gradle 동기화 후 `app`을 실행하거나, JDK 17 이상과 Android SDK 36을 준비해 Windows 터미널에서 다음을 실행합니다.

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest
```

생성된 설치 파일은 `app/build/outputs/apk/debug/app-debug.apk`입니다. 디버그 APK이므로 개인 기기 테스트용입니다. 웹사이트에서 제공하는 APK는 별도의 릴리스 키로 서명하며, 서명 키는 이 저장소에 포함하지 않습니다. Android 휴대전화에서 설치 버튼을 누르면 APK를 내려받고 Android의 설치 확인 절차를 진행합니다. 이전에 디버그 APK를 설치했다면 서명이 달라 제거 후 릴리스 APK를 설치해야 합니다.

## 테스트 및 제한 사항

2026-10-19에 `testDebugUnitTest`, `assembleDebug`, `assembleDebugAndroidTest`, `assembleRelease`가 성공했습니다. Android 15 Pixel 6 에뮬레이터에서 기존 1.0.0 앱 위에 같은 서명 키로 1.1.0을 설치해 앨범 등록 정보가 유지되는지 확인했습니다. 두 앨범 버튼을 고를 때는 복사본이 생기지 않았고, **다음**을 누른 뒤 두 앨범에 각각 같은 사진이 복사됐습니다. 원본과 두 복사본의 SHA-256 해시가 같았으며, **이전 사진 → 다음**을 다시 눌러도 중복 복사되지 않았습니다. 아무 버튼도 고르지 않고 **다음**을 눌렀을 때는 사진을 건너뛰었습니다. 삼성 갤럭시를 포함한 **실기기 동작은 아직 검증하지 않았습니다**.

1.1.1에서 `testDebugUnitTest`, `assembleRelease`, Android 15 에뮬레이터의 계측 테스트 2개가 통과했습니다. 촬영일(EXIF)이 없는 PNG의 원본 수정 시간을 2020-01-01로 설정해 복사한 뒤, 복사본의 MediaStore `DATE_MODIFIED`와 파일 내용이 원본과 같은지 확인했습니다. 이전 릴리스와 같은 서명으로 1.1.1 APK의 업데이트 설치도 성공했습니다. Google 포토 6.84 에뮬레이터에는 **다른 앱의 콘텐츠 표시** 메뉴가 나타나지 않아, 설명서에서 해당 설정을 조건부로 안내하고 보관처리 방법을 함께 설명합니다.

1.1.2에서 `testDebugUnitTest`, `assembleDebug`, `assembleRelease`가 성공했습니다. 같은 서명으로 Android 15 에뮬레이터에 업데이트 설치한 뒤, 홈의 **Google 포토 정리 방법** 안내창이 열리고 **Google 포토 열기** 버튼이 실제 Google 포토 앱을 실행하는지 확인했습니다. 안내창의 스크린샷은 웹 설명서에 포함했습니다.

1.1.3에서 `testDebugUnitTest`, `assembleDebug`, `assembleRelease`가 성공했습니다. 같은 서명으로 Android 15 에뮬레이터에 업데이트 설치해 안내창에 **원본과 복사본을 모두 보관처리**하는 설명이 표시되는지 확인했습니다. 웹 설명서의 실제 앱 화면도 새 버전으로 교체했습니다. Google 포토의 보관처리 자체는 사용자가 Google 포토에서 진행해야 하며, 삼성 갤럭시 실기기 화면은 아직 검증하지 않았습니다.

1.1.4에서는 앱과 웹 설명서에서 Google 포토의 조건부 **앱별 모두 숨기기** 설정을 먼저 안내하고, 사용자가 확인한 사진 화면 맨 위 점 세 개와 실제 설정 경로의 차이를 설명합니다. 앱의 실제 안내 화면을 Android 15 에뮬레이터에서 다시 캡처했습니다. `testDebugUnitTest`, `assembleDebug`, `assembleRelease`, `assembleDebugAndroidTest`가 성공했고, 1.1.3과 같은 서명의 1.1.4 APK가 에뮬레이터에 업데이트 설치됐습니다. 이 버전은 사진 파일 처리 방식이나 기존 복사본을 변경하지 않습니다. Google 포토가 이 앱의 복사본을 인식하고 숨기기 메뉴를 제공하는지는 삼성 갤럭시 실기기에서 확인해야 합니다. Google 포토 보관 상태를 바꾸는 공개 API가 없어 자동 보관은 제공하지 않습니다.

선택한 원본 사진의 접근 권한이 나중에 없어지거나 원본이 삭제되면 다시 선택해야 합니다. 저장소가 분리되었거나 기존 앨범 위치가 바뀐 경우에는 복사를 중단하고 오류를 표시합니다. Android 14 이상의 부분 사진 접근에서는 보이는 앨범과 수량이 전체 갤러리와 다를 수 있습니다. 다른 사진 선택 제공자가 동일한 원본에 매번 다른 URI를 부여하면 여러 작업에 걸친 동일 원본 판별은 제한될 수 있습니다. 복사 직후 진행 기록 저장 전에 기기가 꺼지는 드문 경우에는 해당 복사를 재시도 때 구별하지 못할 수 있습니다.

사진 표시에는 기기의 이미지 디코더를 사용합니다. HEIC/HEIF는 구형 Android 8 기기에서 표시되지 않을 수 있고, AVIF도 구형 OS에서는 표시할 수 없습니다. 표시할 수 없는 사진은 분류를 진행하지 않고 다시 선택하도록 안내합니다. [Android 미디어 형식 지원표](https://developer.android.com/media/platform/supported-formats)를 참고하세요.
