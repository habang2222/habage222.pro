MGlogWH + CONTROL ROOM

로그 수집부터 관제까지,
한 번에 준비하세요.

MGlogWH가 Linux의 파일 열기와 성공한 프로세스 실행 이벤트를 수집합니다. Control Room에서는 같은 컴퓨터의 로그를 검색하고, 규칙과 실행 상태를 살펴볼 수 있습니다. 설치 도우미 하나로 두 프로그램을 함께 준비합니다.

파일을 받은 뒤 실행하세요. Windows에는 WSL2의 Ubuntu-24.04가 먼저 설치되어 있어야 합니다. 설치 중 Ubuntu 계정의 sudo 암호를 요청합니다.

무엇을 할 수 있나요?

Linux 이벤트 수집

파일 열기와 프로세스 실행 기록을 중요도별로 저장합니다. 센서가 실행되는 Linux 환경을 관찰합니다.

브라우저 관제

로그 검색, 등급 필터, 이벤트 상세와 CSV 내보내기를 제공합니다. 손실 관련 상태와 실행 이력도 확인합니다.

규칙 편집

조건에 따라 중요도와 폭주 정책을 정합니다. 규칙 저장 후 별도의 적용 단계에서 새 실행으로 반영합니다.

Windows에서 설치하기

  1. WSL2의 Ubuntu 24.04 준비

    PowerShell의 wsl -l -v로 Ubuntu-24.04와 VERSION 2를 확인하세요. 처음이라면 관리자 PowerShell에서 wsl --install -d Ubuntu-24.04를 실행하고 안내에 따라 재부팅·Ubuntu 사용자 설정을 마칩니다.

  2. 설치 도우미 실행

    위 버튼으로 받은 MGlogWH-Setup.cmd를 더블클릭합니다. 도우미가 Ubuntu를 확인하고 의존성 설치, 소스 빌드, 두 프로그램 설치와 서비스 시작을 진행합니다. 인터넷 연결이 필요합니다.

  3. 관제 화면 열기

    완료되면 http://127.0.0.1:8765가 열립니다. Ubuntu에서 sudo cat /etc/mglogwh-controlroom/token으로 확인한 토큰을 로그인 칸에 붙여 넣으세요.

WSL에서 수집하는 것은 Linux 이벤트입니다. Windows 프로그램의 전체 동작을 수집하는 도구는 아닙니다. WSL의 systemd가 꺼져 있으면 먼저 활성화해야 하며, 도우미가 필요한 조치를 안내합니다.

Ubuntu에서는 명령어 한 줄로

Ubuntu 24.04 x86_64의 일반 사용자 터미널에서 실행하세요. 설치 도우미가 sudo를 요청하며, BTF와 tracepoint 등 커널 지원을 확인합니다. 설치 후 수집 서비스가 시작되어 로그를 디스크에 기록합니다.

curl -fL -H "Authorization: Bearer 내_MGlogWH_API_키" https://habang222.pro/api/v1/programs/mglogwh/files/install-mglogwh.sh -o mglogwh-setup.sh && bash mglogwh-setup.sh

사용 전에 알아두세요

어디에 설치되고 어떤 권한을 사용하나요?

수집기는 /opt/mglogwh, 관제 앱은 /opt/mglogwh-controlroom에 설치됩니다. 설정은 /etc/mglogwh, 로그는 /var/lib/mglogwh에 둡니다. 커널 이벤트 수집과 로그 접근에 root 권한을 사용합니다. 기존 설정과 실행 자료는 설치 도우미가 삭제하지 않습니다.

서버의 관제 화면을 내 PC에서 보려면?

내 PC에서 ssh -L 8765:127.0.0.1:8765 user@server로 SSH 터널을 만들고 http://127.0.0.1:8765를 여세요. 서버 주소와 계정은 직접 바꿉니다. 서비스는 localhost에만 연결하며, 8765 포트를 외부에 열 필요가 없습니다.

로그 수집을 멈추거나 상태를 확인하려면?

sudo systemctl stop mglogwh로 수집을 멈춥니다. 재부팅 후 자동 수집도 끄려면 sudo systemctl disable mglogwh를 실행하세요. sudo systemctl status mglogwh mglogwh-controlroom --no-pager로 상태를 보고, 실패 원인은 sudo journalctl -u mglogwh -n 100 --no-pager에서 확인합니다. 관제 화면 중지는 sudo systemctl stop mglogwh-controlroom입니다.

중요도와 손실 표시는 어떻게 해석하나요?

Critical은 사용자가 정한 중요도이며 공격 판정이 아닙니다. 로그가 손실될 수 있으며, Quarantine 면제도 무손실을 보장하지 않습니다. raw와 손실 원장은 자동 삭제하지 않으므로 디스크 용량과 보존 기간을 관리하세요. 수정본의 전체 성능과 모든 커널에서의 동작은 검증된 상태가 아닙니다.

브라우저가 열리지 않거나 설치가 중단되면?

Ubuntu를 실행한 상태로 http://127.0.0.1:8765를 직접 여세요. 커널이 오래되었거나 WSL localhost 전달이 꺼져 있으면 환경 설정이 필요합니다. 커널 지원 검사는 실제 BPF 로드 성공을 보장하지 않으며, 설치기는 서비스가 실제로 실행되는지 별도로 확인합니다.
